# ADR-026 — Open generic-node document model (Option D)

**Status**: Accepted (2026-08-31)
**Date**: 2026-08-31
**Deciders**: John Peach, with eurAIka Science Council (Round 1+2, 6 members)
**Related**: [ADR-004](ADR-004-mvz-format.md) (`.mvz` = TOML data), [ADR-007](ADR-007-data-sources.md) (pre-computed arrays), [ADR-024](ADR-024-incremental-render-path-bug-f.md) / [ADR-025](ADR-025-embedding-path-live-editing.md) (renderer + embedding, reused here), PLAN-v0.2.md M14, spike `spike/m14d_serializable_fraction.jl`
**Supersedes**: the closed 7-type `PLOT_SCHEMAS` model as the *document representation* (the schema mechanism is generalized, not discarded)

## Decision

FigureViews represents every plot in a document as a **generic, serializable, version-stamped node** — `{id, target, func, args, kwargs, api, meta}` — rather than as one of a closed set of hand-written plot types. The GUI's knowledge of how to build and edit a given plot type comes from a **derived registry** generated by introspecting Makie itself, not from hand-authored per-type code. This is "Option D" from the 2026-08-31 Science Council meeting: represent Makie's *parameter space as data*, not its *syntax as code*.

The existing incremental renderer (ADR-024/025), GLMakie embedding, reactive state tree, and `.mvz` TOML format are **reused unchanged**. This ADR changes the *document representation and the property-panel generation*, not the render path.

## Context

The maintainer's requirement is that FigureViews "not limit Makie." The council evaluated four architectures: (A) keep the closed schema, expand type-by-type (rejected: a solo-dev death march against ~80 moving-target plot functions); (B) a raw-command escape hatch (rejected: breaks the reactive state tree — eval'd calls create Observables the app cannot reach — and forces executable code into `.mvz`); (C) invert to code-as-document / projectional editor (rejected: a research-grade round-trip-fidelity problem, a known graveyard per prior art); (D) generic serializable data nodes.

All four external council members independently converged on D. A measurement spike (`m14d_serializable_fraction.jl`) then tested the deciding unknown and found **96.6% (28/29)** of sampled plot types have primary data inputs fully representable as serializable data, and **95.9%** of attributes serialize cleanly (only 9 distinct benign non-serializable attribute defaults). The lone data-input holdout is `streamplot` (function-valued vector field); `contour`/`contourf`/`surface` accept an optional function form but their primary form is arrays. These function-valued cases fall outside the project's existing pre-computed-arrays data model (ADR-007) and are therefore documented non-goals, not failures.

## The node schema (per-instance, stored in `.mvz`)

Each plot is stored as a node with these fields:

- `id` — stable FigureViews identity (string).
- `target` — explicit parent axis/layout ID. Confirmed by the spike's replay probe: explicit target IDs reconstruct a figure with no reliance on Makie's implicit `current_axis()` state.
- `func` — canonical Makie plot-function identifier (e.g. `"scatter"`), keying into the registry.
- `args` — ordered, typed positional arguments (the plot data), stored as serializable values or data-column references.
- `kwargs` — mapping of attribute name → typed value.
- `api` — the Makie version the node was written against (`makie_major`, `makie_minor`), making compatibility testable rather than inferred.
- `meta` — FigureViews schema version and diagnostic state (`valid` / `unresolved` / `needs_review`).

Because TOML's native types are insufficient for the full supported value domain, `args` and `kwargs` use a typed-value encoding (value + type tag) so reload is unambiguous.

## The registry (per-type, derived, committed as data)

Separate from the per-instance node, a **registry** describes each plot *type*: how to build a node of that type and what widgets edit it. A registry entry is roughly:

```
"scatter" => (
    func             = :scatter,
    conversion_trait = :PointBased,             # from Makie introspection
    positional_shape = [:x_vector, :y_vector],  # derived from convert_arguments
    attributes = Dict(
        :color      => (type=:Colorant, default=:black, widget=:colorpicker),
        :markersize => (type=:Real,     default=9.0,    widget=:numeric),
        ...
    ),
    api    = (makie_major=0, makie_minor=24),
    status = :valid,                            # or :needs_manual_review
)
```

The registry is **generated by introspecting Makie** (`Makie.default_theme`, `Makie.attribute_names`, the `convert_arguments` conversion trait), not hand-authored — so it regenerates on any Makie upgrade by re-running the generator. Registry = schema; node = data. A node references its registry entry by `func` and carries only values, keeping `.mvz` files small.

Types that cannot be cleanly introspected (e.g. `arrows`, deprecated in Makie 0.24 with a 0-attribute ComputeGraph recipe) are emitted with `status = :needs_manual_review` rather than skipped silently or emitted wrong — completeness-with-gaps-flagged, mirroring the preserve-and-warn discipline below.

## The pipeline (frontend + backend merged)

When a user selects a plot type (known or unknown):
1. Instantiate a generic node; pre-populate `kwargs` from the registry (originally `Makie.default_theme(nothing, PlotType)`); inject into the reactive state tree. Stays 100% serializable.
2. On selection, the property panel builds itself from the registry entry: it spawns widgets by attribute type (Colorant→color picker, Real→numeric) and binds them bidirectionally to the node's fields. Known common types may override with a hand-crafted panel; unknown types get the generic key-value panel as an explicit fallback tier.
3. On edit, the existing `apply_structural!` renderer passes `args` through `Makie.convert_arguments(PlotType, args...)`, rehydrates the ~4% non-serializable attributes via a curated `Symbol→Function`/enum registry (e.g. `"identity"` → `identity`), and dispatches `plot!(target_axis, PlotType, converted_args...; kwargs...)` into the live figure.

## Loading contract: preserve-and-warn

Loading an `.mvz` must **never destroy information because the current Makie cannot interpret it**. If a Makie upgrade renames or removes an attribute, the loader preserves the original key/value, marks the field `unresolved`, warns, and re-saves it intact. Rendering of a degraded node: **refuse-to-render with a visible placeholder** rather than partial-render, because a scientific tool must not silently produce a scientifically different figure. (This resolves the council's open question in favor of the stronger guarantee.)

## Round-trip fidelity: the closure trap and its mitigation

The one round-trip hazard is user-supplied function/closure attribute values, which cannot be reconstructed from a string safely. Mitigation is a **design constraint, not a technology**: the property panel never exposes a free-text lambda field — function-valued attributes use fixed-choice selectors — so the reload domain stays finite (a hand-curated `Symbol→Function` registry of Makie exports + enum discriminants). This converts a compiler-grade problem into a bounded data-dictionary task.

## Phased build order (M14)

Sequenced to resolve the full-introspection-vs-registration-table tension by ordering rather than choosing, and to protect against scope creep (Perplexity's evidence that auto-generated panels are universally second-class; Grok's standing caution that "never limit Makie" expands scope without bound):

1. **Phase 1 — generic-node foundation.** Refactor the 7 existing plot types to store as generic nodes; define the registry-entry struct; add types via the registry. `.mvz` stays pure TOML; renderer unchanged. Load-bearing, low-risk.
2. **Phase 2 — registry generator.** Promote the spike's introspection into a committed generator that emits registry entries across the full plot-type list, marking un-introspectable types `needs_manual_review`. The "dictionary" of plot types, generated not authored.
3. **Phase 3 — generic property panel** (fallback tier, explicitly not over-invested), **non-serializable registry**, **preserve-and-warn loading**, and a **full round-trip test suite** (save→load→render equivalence across sampled types).

**Deferred indefinitely (gold-plating until a real user hits the limit):** first-class `streamplot` vector-field serialization, arbitrary-closure editing, full third-party-recipe auto-discovery, nested-struct panel editing.

## Consequences

- The closed `PLOT_SCHEMAS` model is generalized to the open node+registry model. The mechanism (schema-driven property panel) survives; the closed enumeration does not.
- New plot types become *data* (a registry entry) rather than *code* (a hand-written schema + render branch), removing the solo-dev velocity ceiling.
- `.mvz` remains pure TOML data (ADR-004 preserved), now with a version stamp per node.
- The renderer, embedding, and reactive tree (ADR-024/025, M12/M13) are reused unchanged — no rework.
- Estimated remaining effort (DeepSeek, council): ~13 weeks solo, with the reusable layers saving 5–6 weeks; +2 weeks if first-class streamplot is later required.
- Function-defined plots (streamplot; f-forms of contour/surface) are explicit non-goals, consistent with ADR-007.
